# USB4 constraint table and next observations

Generated by the offline investigation runner. T = true, F = false, ? = unknown. This is an abstract milestone model, not a USB port or controller emulator.

A coarse milestone abstraction for one recorded attachment episode and its follow-up snapshot. Ever reached and final present are different facts. Sources span trace/snapshot reporting, not a common physical wire clock. Entry means admission to USB4-domain operation, including compatible mode where applicable; it does not mean a native Enter_USB packet was captured. Failure-stage rows partition the modeled unfinished milestone, not the root cause. Exit is a cross-cutting event. Logical combinations have no assigned probability.

## Variables and observation limits

| Variable | Meaning | What a real observation must establish |
| --- | --- | --- |
| E | Domain-mode entry was achieved at least once in this episode | Requires an understood entry/history witness. A cached NotAttemptedOrExited code is unknown; an inferred domain milestone is not a captured native Enter_USB request/Accept. |
| L | A usable USB4-domain link existed at least once | A qualified positive link-ready sample can witness this. A negative current sample cannot prove never-ready; that requires validated event/history coverage. |
| R | An operational external router was established at least once | Requires a fresh, correctly owned operational-router witness. A cached node, a capability bit or merely identifying a register is insufficient. |
| F | The external router is present at the final recorded observation | A recorded topology/inventory result is scoped to its snapshot. It does not establish whether a router existed earlier. |
| X | Domain-mode exit occurred after an entry during this episode | Requires understood ordered history. Exit may occur before usable link/router creation; later re-entry is allowed. No captured exit is unknown without complete coverage. |
| C | Captured normal host UCSI exchanges completed successfully | The captured commands/completions and CCI errors can establish this control-path fact. It has no implication to E, L or R. |

## Declared assumptions

- `L ⇒ E`: For this coarse model a valid domain link follows successful domain-mode admission. A contradictory record requires checking field meaning, timestamps and this assumption.
- `R ⇒ L`: An operational external router requires a usable domain link; stale software objects are excluded from R's definition.
- `F ⇒ R`: A genuinely present operational router at the final observation is also an ever-present witness.
- `X ⇒ E`: X is specifically an exit after entry. It is not a generic disconnect, failed request or descriptor error.

C is deliberately independent of the USB4 milestone chain. X is a cross-cutting exit/history event: it is not a mutually exclusive failure stage, and later re-entry is not forbidden.

The chain describes successful domain-mode/link/router milestones, including a compatible mode where applicable. It does not equate an inferred milestone with a recorded native Enter_USB packet. No probabilities are assigned to enumerated combinations.

## Automation boundary

The runner validates pinned evidence, applies explicit source rules, enumerates consistent milestone combinations, ranks ideal discriminating observations and refreshes the reports. It cannot supply an unrecorded PD exchange or electrical measurement. A Device Manager disable/enable, a synthesized PnP notification and a physical cable insertion are different interventions. No hotplug simulation, reset, driver load or capture session is part of this pipeline.
