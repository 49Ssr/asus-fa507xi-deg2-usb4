# Research and maintenance rules

This is an unresolved hardware compatibility investigation, not a published fix.
Keep confirmed observations, hypotheses, ineffective tests, and unperformed tests distinct.
Record meaningful mistakes and corrections. Never claim that successful driver installation proves a firmware update or working USB4 link.

`local/` contains private evidence, signed third-party driver copies, and temporary operating-system files. It is excluded from Git. Do not publish its contents or raw ETL/XML/PnP inventories. Public evidence must remove serial numbers, computer/user names, account addresses, device instance suffixes, MAC addresses, router/domain UUIDs, private paths, and support case identifiers.

Use original FA507XI driver packages for the temporary Windows baseline. Never inject a Firmware-class package, cross-flash another model's firmware, alter Secure Boot/test-signing, or patch Windows binaries as a routine troubleshooting step.

The native boot toolkit must default to Preview. It may initialize/format only a newly created, exactly associated file-backed virtual disk, and must never clean, resize, format, or repartition a physical disk. Keep the original Windows default and UEFI boot order. Do not automatically reboot. Delete only the toolkit's verified boot entry during cleanup; retain results and the VHDX for explicit review.

Validate scripts under Windows PowerShell 5.1. Test safety guards and command plans without executing disk, boot, driver-installation, or firmware operations in tests. Hardware results must be recorded separately from mocked tests.

Preserve the owner's network configuration during eGPU diagnosis. UGREEN USB Ethernet is the intended Internet source; built-in PCIe Ethernet supplies the second laptop through Internet Connection Sharing. Before any further device removal or controller reinstall that can affect the USB NIC, save private adapter identities/GUIDs, aliases, IP/DHCP/DNS settings, routes and ICS bindings. Do not substitute the USB4 peer adapter, DEG2 Ethernet or Wi-Fi Direct as the sharing destination without an explicit request. Passive capture tools must not change networking. The earlier USB controller subtree removal could have recreated the USB NIC; that cause has not been established from its changed alias alone.

The owner subsequently explicitly requested a deeper negotiation capture aimed at an evidence-backed custom solution. Its documented UCSI test-interface preparation and exact undo are the authorized narrow change; this does not authorize restoring unrelated experiments or running another blanket controller reinstall. Keep the native-boot maintenance toolkit while its test installation exists, and preserve real captures, memory evidence and private support records.

The owner then explicitly authorized a portable direct Intel Dell-DEG2 control. Capture-DellDEG2Control.ps1 imports the exercised primitives through the ASUS source without invoking its entry point. Keep the ASUS model/hash guards unchanged. The Dell entry point separately validates its manufacturer, Intel host router and any selected Microsoft ACPI UCSI device, saves original state before enabling the documented test interface, and restores it after owner-confirmed DEG2 disconnection. Keep binaries, symbol caches, driver snapshots and USB results private. Native tests on the existing ASUS dump validate the package, not Dell hardware operation.

The prepared TestModeExit experiment is a separate explicit mode. Keep InspectModes GET-only. TestModeExit permits only one SET_NEW_CAM EXIT for the freshly verified connector 1/current index 1 target, with zero mode-specific data and advertised override support. Preserve existing host/tool guards, stop further firmware commands on failed GET or uncertain EXIT, and retain its owned trace and intent/replies. Do not widen it into automatic mode entry, role switching, resets or repeated requests. Mocked validation is not hardware success.
